# n8n Workflows — Upwork Radar

Three importable workflow templates. They implement the pipeline:

```
Gmail alert → 01 Intake → 02 Scoring → (>=9) → instant Gmail alert
  04 Daily Digest (scheduled, 08:00)
```

Proposal drafts are **not** generated by n8n — they are generated on demand from
the dashboard's job page (the "Generate proposal" button calls DeepSeek directly
from the Next.js server). This keeps AI costs tied to your actions.

## Files

| File | Purpose | Trigger |
|---|---|---|
| `01_intake.json` | Parse Upwork alert email, upsert into `jobs`, hand off to scoring | Gmail trigger (poll) |
| `02_scoring.json` | Load profile + portfolio, DeepSeek score, insert `job_scores`, instant alert on >= 9.0 | Called by 01 |
| `04_daily_digest.json` | Daily email of jobs scored >= 7 in the last 24h | Cron `0 8 * * *` |

## Import

1. In n8n, **Workflows → ⋯ → Import from File** for each file.
2. **Credentials** (create + attach):
   - **Gmail OAuth2** (Google Cloud project, Gmail API enabled) → attach to the *Gmail Trigger*, *Instant Alert (Gmail)*, and *Send Digest (Gmail)* nodes.
   - No credential needed for the HTTP Request nodes — they read env vars.
3. **Re-link the sub-workflow** (required after import, IDs change):
   - In `01_intake.json` → node **Run Scoring**: select the `02 - Scoring` workflow.
   - The child workflow starts with an *Execute Workflow Trigger* node — keep that node first.
4. Turn each workflow **Active** when ready to run.

## Environment variables (n8n instance)

Set these in the n8n process env (e.g. `n8n.env` / Docker `environment`):

| Variable | Value |
|---|---|
| `SUPABASE_URL` | `https://<project-ref>.supabase.co` |
| `SUPABASE_SERVICE_ROLE_KEY` | Service role key from Supabase → Settings → API. **Never expose this to the browser.** |
| `DEEPSEEK_API_KEY` | DeepSeek console API key |
| `RADAR_EMAIL` | Email address the digest + instant alerts are sent to |
| `RADAR_DASHBOARD_URL` | (optional) Deployed dashboard URL used in the digest footer |

## Upstream requirements (Supabase)

- `supabase_migrations.sql` run in the SQL Editor first.
- Then `supabase/00_extensions.sql` (adds `skipped_at`, `skip_reason`, unique `jobs.url` index).
- Then `supabase/01_rls_policies.sql` and `supabase/02_views.sql`.
- Run `supabase/03_seed.sql` so a profile row exists (scoring fails without it).
- n8n writes via the **service role** key, which bypasses RLS. RLS still protects the dashboard's authenticated reads.

## Getting jobs faster (latency)

Two delays decide how "fresh" a job is when you see it:

1. **Upwork alert frequency (the #1 lever).** Upwork batches saved-search
   emails unless you opt into instant alerts. Set: Upwork → **Job Settings →
   Job alerts → Frequency → Immediately**. Until you do this, no polling rate
   in n8n will help — the email itself arrives late.
2. **n8n Gmail polling.** The Gmail trigger in `01_intake.json` polls every
   **1 minute**. Gmail uses delta polling via `historyId`, so this is light on
   quota.

End-to-end timing with both set: Upwork emails instantly → n8n picks it up
within 1 min → parse + DeepSeek score in ~10–30 s → job is in the dashboard
and, if ≥ 9.0, an instant Gmail alert fires. You should be seeing jobs minutes
after they're posted — not hours.

**Reality check:** even with instant intake, high-demand posts will still
accumulate proposals fast because other freelancers (and automated bidders)
react quickly. Instant intake gets you into the first wave; it does not beat
speed-based auto-submission (which is against Upwork terms and intentionally
not part of this system).

## Parsing notes

- `01_intake.json` → **Parse Email** code node contains regexes tuned to Upwork alert emails. Your saved-search alert layout may differ: run one email through the workflow and adjust the regexes (title / URL / skills / budget).
- Emails missing `title`, `url`, or `description` are routed to `manual_review_queue` instead of `jobs`.

## Safety

- Proposals are **drafts only**, generated on demand from the dashboard. Nothing is ever auto-submitted to Upwork.
- DeepSeek output is validated before insert: score ranges, recommendation enum, and (for dashboard proposals) word count. Invalid output fails the execution so it shows in n8n as an error.
