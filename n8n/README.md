# n8n Workflows — Upwork Radar

Importable workflow templates. They implement the pipeline:

```
Gmail alert → 01 Intake → 02 Scoring → (>=9) → instant Gmail alert
ATS boards → 05 ATS Intake → 02 Scoring → (>=9) → instant Gmail alert
  04 Daily Digest (scheduled, 08:00)
Website URL → 10 Audit Pipeline → crawl, analyze, score, opportunities
Audit findings → 11 Audit Pitch → personalized outreach pitch
```

Proposal drafts are **not** generated by n8n — they are generated on demand from
the dashboard's job page (the "Generate proposal" button calls DeepSeek directly
from the Next.js server). This keeps AI costs tied to your actions.

## Files

| File | Purpose | Trigger |
|---|---|---|
| `01_intake.json` | Parse Upwork alert email, upsert into `jobs`, hand off to scoring | Gmail trigger (poll) |
| `02_scoring.json` | Load default profile + portfolio, DeepSeek score, insert `job_scores`, instant alert on >= 9.0 | Called by 01 and 05 |
| `04_daily_digest.json` | Daily email of jobs scored >= 7 in the last 24h | Cron `0 8 * * *` |
| `05_ats_intake.json` | Poll watched company ATS boards, filter by 4-pillar keywords, upsert jobs, hand off to scoring | Cron every 12 hours |
| `10_audit_pipeline.json` | Website audit: page discovery, crawling, technology detection, AI issue analysis, scoring, opportunity detection | Webhook POST `/audit` |
| `11_audit_pitch.json` | Generate personalized outreach pitch from audit findings and selected opportunities | Webhook POST `/audit/pitch` |
| `12_outbound_send.json` | Send approved outbound emails via Gmail, then report delivery back to the dashboard | Webhook POST `/outbound-send` |

## Import

1. In n8n, **Workflows → ⋯ → Import from File** for each file.
2. **Credentials** (create + attach):
   - **Gmail OAuth2** (Google Cloud project, Gmail API enabled) → attach to the *Gmail Trigger*, *Instant Alert (Gmail)*, and *Send Digest (Gmail)* nodes.
   - No credential needed for the HTTP Request nodes — they read env vars.
3. **Re-link the sub-workflows** (required after import, IDs change):
   - In `01_intake.json` → node **Run Scoring**: select the `02 - Scoring` workflow.
   - In `05_ats_intake.json` → node **Run Scoring**: select the `02 - Scoring` workflow.
   - The child workflow starts with an *Execute Workflow Trigger* node — keep that node first.
4. Turn each workflow **Active** when ready to run.

## ATS Intake (05_ats_intake.json)

The ATS workflow polls your watched company list (managed from the dashboard's
Settings page) every **6 hours**. It supports Greenhouse, Lever, Ashby,
Workable, SmartRecruiters, and Recruitee public APIs. Personio is listed but
has no public API — those entries are skipped.

Latency note: new jobs appear within ~6 hours of being posted on the company's
careers page. This is intentional — ATS boards are low-churn compared to Upwork,
so 6-hour polling keeps the signal fresh without excessive traffic.

The workflow:
1. Loads active companies from `watched_companies`
2. Fetches jobs from each company's ATS API
3. Filters by broad 4-pillar keyword match (design / build / automation / growth)
4. Upserts into `jobs` (source = `ats_api`, deduped on URL)
5. Only new (non-duplicate) jobs are handed to the scoring sub-workflow

## Environment variables (n8n instance)

Set these in the n8n process env (e.g. `n8n.env` / Docker `environment`):

| Variable | Value |
|---|---|
| `SUPABASE_URL` | `https://<project-ref>.supabase.co` |
| `SUPABASE_SERVICE_ROLE_KEY` | Service role key from Supabase → Settings → API. **Never expose this to the browser.** |
| `OWNER_USER_ID` | `auth.users.id` of the owner automation user. Required — service-role inserts bypass RLS and must stamp every row with `user_id` (17_multi_user_rls.sql). Find it: `select id from auth.users limit 1`. |
| `DEEPSEEK_API_KEY` | DeepSeek console API key |
| `N8N_WEBHOOK_SECRET` | Shared secret for the incoming webhooks. Must match the **Header Auth (Bearer)** credential attached to the audit/outbound webhook listeners and the app's `N8N_WEBHOOK_SECRET`. |
| `RADAR_EMAIL` | Email address the digest + instant alerts are sent to |
| `RADAR_DASHBOARD_URL` | (optional) Deployed dashboard URL used in the digest footer |
| `NEXT_PUBLIC_APP_URL` | Public dashboard URL. Used by `12_outbound_send.json` to call back `/api/outbounds/report`. |

## Website Auditor (10_audit_pipeline.json)

The audit workflow is triggered via webhook when a user starts an audit from the
dashboard. It:

1. Receives `{ audit_id, url }` via POST
2. Discovers pages via sitemap.xml + priority page list
3. Crawls each page (basic HTTP fetch — replace with Playwright community node for full browser rendering)
4. Extracts technology fingerprints (WordPress, Shopify, Calendly, Jotform, HubSpot, GA, GTM, etc.)
5. Saves page data to `audit_pages` and technologies to `audit_technologies`
6. Calls DeepSeek for AI issue analysis (UX, UI, performance, accessibility, SEO, conversion)
7. Saves issues to `audit_issues`
8. Computes dimension scores (ui, ux, performance, accessibility, seo, conversion, overall, automation)
9. Calls DeepSeek again for opportunity detection (lead capture, appointment booking, CRM, email, WhatsApp, etc.)
10. Saves opportunities to `audit_opportunities`
11. Marks audit as completed

**Playwright upgrade:** For full browser rendering, screenshots, and axe-core
accessibility testing, replace the **Crawl Page** code node with the
`n8n-nodes-playwright` community node. Set `PLAYWRIGHT_BROWSERS_PATH` and use
the `mcr.microsoft.com/playwright:v1.58.0-noble` Docker base image.

**PageSpeed Insights:** For Lighthouse scores, add a PageSpeed Insights API call
(free tier, ~25k queries/day) instead of installing Lighthouse CLI in the n8n
container.

## Audit Pitch (11_audit_pitch.json)

Triggered on-demand from the audit detail page. Receives `{ audit_id, opportunity_ids[] }`,
loads audit context, technologies, issues, and selected opportunities, then calls
DeepSeek to generate a personalized outreach pitch with subject line and key talking points.

## Upstream requirements (Supabase)

- `supabase_migrations.sql` run in the SQL Editor first.
- Then `supabase/00_extensions.sql` (adds `skipped_at`, `skip_reason`, unique `jobs.url` index).
- Then `supabase/01_rls_policies.sql` and `supabase/02_views.sql`.
- Run `supabase/03_seed.sql` so a profile row exists (scoring fails without it).
- **Then `supabase/17_multi_user_rls.sql`** (adds `user_id` isolation; run AFTER the first auth user exists so the backfill has an owner).
- **Then `supabase/18_rate_limits.sql`** (server-side rate limiting table).
- n8n writes via the **service role** key, which bypasses RLS. After 17, every n8n insert must pass `user_id` explicitly — the workflows use `$env.OWNER_USER_ID`, so set that env var. RLS still protects the dashboard's authenticated reads and scopes every row to its owner.

## Getting jobs faster (latency)

Two delays decide how "fresh" a job is when you see it:

1. **Upwork alert frequency (the #1 lever).** Upwork batches saved-search
   emails unless you opt into instant alerts. Set: Upwork → **Job Settings →
   Job alerts → Frequency → Immediately**. Until you do this, no polling rate
   in n8n will help — the email itself arrives late.
2. **n8n Gmail polling.** The Gmail trigger in `01_intake.json` polls every
   **1 minute**. Gmail uses delta polling via `historyId`, so this is light on
   quota.

End-to-end timing with both set: Upwork emails instantly → n8n picks it up
within 1 min → parse + DeepSeek score in ~10–30 s → job is in the dashboard
and, if ≥ 9.0, an instant Gmail alert fires. You should be seeing jobs minutes
after they're posted — not hours.

**Reality check:** even with instant intake, high-demand posts will still
accumulate proposals fast because other freelancers (and automated bidders)
react quickly. Instant intake gets you into the first wave; it does not beat
speed-based auto-submission (which is against Upwork terms and intentionally
not part of this system).

## Parsing notes

- `01_intake.json` → **Parse Email** code node contains regexes tuned to Upwork alert emails. Your saved-search alert layout may differ: run one email through the workflow and adjust the regexes (title / URL / skills / budget).
- Emails missing `title`, `url`, or `description` are routed to `manual_review_queue` instead of `jobs`.

## Safety

- Proposals are **drafts only**, generated on demand from the dashboard. Nothing is ever auto-submitted to Upwork.
- DeepSeek output is validated before insert: score ranges, recommendation enum, and (for dashboard proposals) word count. Invalid output fails the execution so it shows in n8n as an error.
